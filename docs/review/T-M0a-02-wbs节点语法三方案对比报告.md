# T-M0a-02 · wbs.md 节点语法三方案 round-trip 对比报告

> 任务：T-M0a-02 ｜ 日期：2026-10-19 ｜ 原型：`src/core/wbsSyntax.ts` ｜ 测试：`src/core/wbsSyntax.test.ts`（17 用例）
> 结论建议见《[wbs节点语法定稿](../design/wbs节点语法定稿.md)》，随 G-M0a 提请主理人过目。

## 一、目的与方法

基准 MOD-02 要求 wbs.md 节点 frontmatter 语法以三方案对比原型定稿：**fenced block / HTML comment / 独立任务文件**，用真实含注释样本做 round-trip 验证。本报告基于同一套原型代码与同一测试样本集，比较三方案在统一契约下的实测表现。

统一契约（R-04/P-04 的可执行口径）：

1. 解析只定位节点区间，节点内部原文（raw）原样保留；
2. 未知字段、重复字段、未解析行一律保留并出诊断（F-06）；
3. `reconstruct(parse(md))` 与原文字节级一致（含用户注释、空行、CRLF、EOL 风格）；
4. `updateField` 只改动目标字段值文本，不动节点内其他字节。

## 二、三方案原型

| 方案 | 语法 | 解析入口 |
|---|---|---|
| A · fenced block | `~~~gatedeck-task` … `~~~`（反引号/波浪线皆可，CommonMark 闭合规则） | `parseFencedTaskBlocks` |
| B · HTML comment | `<!-- gatedeck:task` … `-->` | `parseHtmlCommentTasks` |
| C · 独立任务文件 | 每任务一文件，YAML 风格 frontmatter（`---` 包裹） | `parseStandaloneTaskFile` |

三方案共用同一字段行语法：`key: value`，key 以 Unicode 字母/下划线开头（允许中文未知字段）；共用 span + raw + wrapper 结构与 `reconstruct` / `updateField` 机制。

## 三、实测对比矩阵

| 维度 | A · fenced block | B · HTML comment | C · 独立任务文件 |
|---|---|---|---|
| round-trip 字节级保真 | ✅ 实测通过（LF/CRLF） | ✅ 实测通过 | ✅ 实测通过（LF/CRLF） |
| 未知字段/中文键保留 | ✅ 保留并诊断 | ✅ 保留并诊断 | ✅ 保留并诊断 |
| 机器字段人类可见性 | ✅ 渲染可见、可审 | ❌ 渲染隐藏，编辑器"清理注释"易误删 | ✅ 每文件 frontmatter 可见 |
| 单文件树状总览 | ✅ wbs.md 单文件承载 | ✅ 单文件承载 | ❌ 48 任务 = 48 文件，总览需另建投影 |
| 结构性冲突（实测样本） | ⚠️ 内层同字符 fence 被当作闭合（冲突样本复现）；缓解：节点内代码块用不同字符或加长 fence，lint 告警 | ❌ 值中出现 `-->` 提前终止注释（死锁样本复现，后续字段静默落在节点外）；注释不可嵌套 | ✅ 无语法嵌套冲突 |
| git diff 粒度 | 单文件集中 diff | 单文件集中 diff | 细粒度，但跨文件操作原子性弱（P-06 成本×N） |
| 路径兼任身份风险 | 无 | 无 | 有（文件路径即身份，违背 D-27"路径不兼任身份"取向） |
| 解析实现复杂度 | 低（逐行 + fence 配对） | 低（indexOf 扫描） | 低 |
| 与 changelog 事件块同构 | ✅ 同一包裹机制可复用（T-M0a-03 同批原型） | ✅ 同构 | ⚠️ 事件在 changelog.md 单文件 append-only，C 方案形态不成立 |

## 四、关键实测发现

1. **方案 A 冲突样本**：节点内出现与外层同字符、足够长度的裸 fence 行会被当作闭合，后续内容落在节点外——原文不丢失（round-trip 仍成立），但节点字段静默截断。缓解约定成立：节点内代码块改用另一 fence 字符（外层 `~~~` / 内层 ```）或加长外层 fence；该冲突可由 lint 静态检出（T-M2a-02 高危模式告警的同族）。
2. **方案 B 死锁样本**：字段值包含 `-->` 时注释提前终止，`status: todo` 等后续字段静默丢失在节点外且**无任何诊断**——比方案 A 的冲突更危险（无检测手段）。HTML 注释不可嵌套是语法级死结。
3. **方案 C**：round-trip 最干净，但 48 任务 48 文件打散了 wbs.md 的单文件事实源地位（基准 3.1：任务内容与状态唯一权威位置 = `pm/wbs.md`），且每任务一文件使 P-06 跨文件四相恢复的事务面扩大 N 倍。
4. 统一契约下三方案 round-trip 全部字节级通过——**保真机制（span+raw+wrapper）与包裹语法无关**，定稿的关键判据是结构性风险与人类可见性，而非保真能力。

## 五、结论建议

**定稿建议：方案 A（fenced block）**，理由按权重：

1. 机器权威字段人类可见可审（R-04 的精神：用户文件神圣，机器字段不得藏进不可见区域）；
2. 单文件承载树状任务谱，守住 wbs.md 唯一权威位置（基准 3.1）；
3. 结构性冲突可缓解、可 lint 检出；方案 B 存在无诊断的静默截断死结，方案 C 打散单文件事实源并放大并发事务面；
4. 与 T-M0a-03 事件块语法同构，一套包裹机制两处复用，降低契约碎片化风险（风险 5）。
