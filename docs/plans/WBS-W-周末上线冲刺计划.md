## 【计划】具体实施的计划

### 1. 冲刺策略（为什么是 rc 而不是正式 v0.1.0）

现状：M0a 完成 6/7、M0b 完成 5/9，距正式 v0.1.0 尚有约 36 项任务，且 G-M1 明确要求「自举 **2 周**三项度量」、G-M3 要求「外部用户接入验证 + 人工签认」——这两条**物理上不可能在周末达成**。

因此本冲刺采用两条原则：

1. **垂直切面**：不做完 M1~M3 全部任务，而是打通用户可感知的最短价值路径（接入 → 决策台 → 证据链 → 交接 → AI 经 MCP 接管），其余任务显式后补；
2. **诚实降级**：周末上线 **v0.1.0-rc.1**（npm dist-tag `early`），正式 v0.1.0 仍按原门禁走（预计 11 月中下旬，2 周自举度量自 10-25 起算）。rc 不冒充正式版，所有对外文案明示 early access。

### 2. 价值准出（999 元价值锚 · 冲刺验收线）

上线产物须让一个「单人开发者 + AI 结对」用户在体验后认同「这值 999 元」：

| # | 准出项 | 判据 |
|---|---|---|
| V1 | 5 分钟接入 | 陌生环境 `npx gatedeck@early` → `pm init` → 首屏决策台可见 |
| V2 | 3 分钟接管 | 新 AI 会话经 workBuddy（get_overview + get_wbs）准确复述项目状态并指出下一步 |
| V3 | 证据可复验 | `check_gate` → `request_promotion` → TTY 确认 → 状态迁移，全链路可重放 |
| V4 | 本地优先可证 | 断网可用；数据纯 Markdown，可 `git diff`、可迁移 |
| V5 | 文档与支持 | 双语 README + 接入指南 + FAQ + 回滚说明齐备 |
| V6 | 稳定性底线 | CI 绿（云端真实首跑）+ 干净环境冒烟 + npm 回滚路径演练 |

#### 3.1 门禁 DeepSeek 双轮审核机制（主理人授权 2026-10-23，限本冲刺）

**授权内容与边界**（R-03 授权有痕）：

- 本冲刺内的门禁准出审核（G-M0a / G-M0b 的「经主理人过目」环节）由 DeepSeek 模型执行，**至多 2 轮，2 轮复审后即视为审核通过**；
- 授权**不覆盖**：① 门禁开启动作（仍由主理人人工执行，AI 不得代开）；② 硬性准出条件（必需任务 done / 三类合成样本全过 / CI 云端真实绿）——这些不可由审核替代（W-06）；若轮 2 复审后仍存在致命级问题（即硬条件不满足），门禁不开，按 R1 停摆或主理人现场裁决；
- 授权**仅限本冲刺**：正式 v0.1.0 前的门禁（G-M1~G-M3）回归基准原制度（人工过目与人工签认）。

**审核协议**：

1. 材料包：五项设计文档 + M0 演练证据 + CI 证据，经脱敏检查后按 token 预算封装（见下）；
2. 轮 1：DeepSeek 审核产出问题清单（分级：致命 / 一般 / 建议）；
3. 修复轮 1 问题 → 轮 2 复审；
4. 轮 2 后：无致命问题 → 审核通过，门禁准出成立，主理人开启；仍未关闭的一般/建议项**逐项写入遗留清单**。

**遗留清单与触发式修复**（清单：`docs/review/WBS-W-门禁审核遗留清单.md`，CP-2 时创建，由 W-S5-3 常态值守）：

- 每项记录：问题 ID / 来源门禁 / 轮次 / 分级 / 影响面（关联 WP 与模块）/ 状态（open → in-fix → re-review → closed）/ 修复与重审记录；**轮次审核记录 append-only**，状态迁移在行内留痕；
- **触发规则**：后续任一 WP 开工或执行中一旦命中清单问题的影响面 → **必须先修复该问题项** → 修复内容重新送 DeepSeek 审核（单问题项复审）→ **closed 后该 WP 方可继续或验收**；
- 清单在冲刺收尾（W-S5-1）时全量盘点，open 项随 rc 诚实边界对外披露。

**token 口径（按项目既有设计执行，不另立标准）**：

- 材料包预算：按 MOD-06 `pm handoff` 的软预算机制——token 数按分词器估算或标字符数、软预算超限明确提示不静默裁剪（B-8）；材料包封装时标注估算值，超限裁剪显式留痕；
- 消耗记录：每轮审核实际消耗按 T-M2a-05 / MOD-08 用量契约字段（日期 / 项目 / 模型 / 输入输出 token / 关联任务 / 来源 / actor_id/session_id）如实记录；rc 期 report_usage 机制未实现 → 手工记入清单留痕区（有真实值记真实值，无计量不猜）。

**材料脱敏（W-01 / W-02 不随授权豁免）**：审核材料仅含 gatedeck 本项目文档与测试摘要；密钥、`.local/` 内容、其他受管项目数据（`pm/`）一律不入包。
