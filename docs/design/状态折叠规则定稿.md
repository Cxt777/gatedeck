## 一、定稿结论

1. **按可信 sequence 折叠，不按 occurred_at**（B-16）：sequence 来自收据链 `receipt.seq`（T-M0a-04），occurred_at 仅展示；输入乱序传入亦按 seq 排序折叠。
2. **参与推导门槛**（P-09）：有效 integrity=verified **且** origin=core **且** 有链序；unknown/invalid 不参与授权/检查/进展推导，manual 永不驱动状态。
3. **重复 event_id 幂等**（B-13）：首笔参与折叠，后续同 id 出 `duplicate-event-id` 诊断、不产生二次推进。
4. **补偿/撤销走追加事件**：correction 引用原 promotion 事件（append-only，不改写历史）。

## 二、三类驱动事件的 payload 契约（M0a 提议，随 G-M0a 提请确认）

| kind | payload | 折叠行为 |
|---|---|---|
| `project.initialized` | `{ project_id, stage_order: string[] }`（stage_order=gates.md 阶段序，初始化时由 core 读入） | 记 stageOrder；初始阶段 = `stage_order[0]`（gates.md 首阶段） |
| `promotion.completed` | `{ from, to, expected_sequence, manifest_hash? }` | 全部通过才推进：from=当前阶段；to=当前阶段的下一阶段（**非法跳跃拒绝**）；expected_sequence=本事件链序（**重放防护**：事件被复制到其他链位置即序号不符拒绝） |
| `correction` | `{ target_event_id, revert_to }` | 仅可引用已生效 promotion 且 `revert_to = 原 promotion.from`（只能退回推进前阶段）；否则 `correction-rejected` |

被拒绝的推进/补偿：**事件保留在流中**（append-only），投影记 `promotion-rejected` / `correction-rejected` 诊断与原因，不静默丢弃。

其余 core kind（check.completed / authorization.* / operation.recovery）不影响阶段派生，属其他投影维度（检查事实/授权/恢复，M0b/M1 展开）。

## 三、投影输出（派生态，不落 project.md，D-24）

`StageProjection { currentStage, stageOrder, transitions, asOf, sourceVersion, attention, diagnostics }`：

- `asOf` = 最后**被消费**参与事件的 recorded_at（含被拒绝事件——as_of 回答「投影基于哪个时点的事件流」）；
- `sourceVersion` = 被消费参与事件笔数（供 T-M0b-06 compare-and-set）；
- `attention`（「需处理」，B-11）：收据链问题透传（chain 来源）+ 折叠异常（fold 来源，如 init 缺 stage_order）；**投影正常也不吞链级问题**。
