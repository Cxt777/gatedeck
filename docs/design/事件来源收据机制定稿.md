## 一、定稿结论

1. **收据只为 core 权威事件生成**（origin=core）；managed-api/manual 事件不入链，加载时按 S2.1-04 判定 external-unverified（有效 integrity=unknown，不参与状态推导）。
2. **哈希算法固定 SHA-256**，core 内置纯函数实现（`src/core/hash.ts`，FIPS 180-4）——core 纯度约束禁止 `node:crypto`，且纯实现可跨机复算、与 openssl 互验；实现经 node:crypto 多向量对拍（含多字节中文、56 mod 64 填充边界）。
3. **收据条目**：`{ event_id, seq, content_hash, prev_hash, receipt_hash }`；
   - `content_hash = sha256(serializeEventBlock(envelope))`——与 T-M0a-03 序列化**同源**，杜绝双口径；
   - `receipt_hash = sha256(prev_hash|event_id|seq|content_hash)`——链式绑定内容与顺序；
   - `seq` 从 1 起严格递增，**即 B-16「可信 sequence」的 sequence 来源**（T-M0a-05 折叠排序依据）。
4. **锚点**：`{ schema_version, algorithm, chain_head, length, generated_at }`，对链头做承诺；存 git 忽略的本地安全位置，**位置与读写由存储层（M0b）承接**，core 只定义 schema 与验证语义。
5. **验证裁定（加载时，内容+顺序）**：见 2.1。

## 二、验证裁定规则（verifyEventChain）

### 2.1 逐块裁定

| 情形 | 裁定 | 依据 |
|---|---|---|
| event_id 未在收据链登记 | `unregistered`（有效 integrity=unknown） | S2.1-04 external-unverified |
| 事件内容哈希 ≠ 收据 content_hash | `invalid` | B-10 伪造/篡改 |
| 锚点与复算链头不符（或收据链复算断裂） | **全链** `invalid` | B-11，宁严勿漏 |
| 有收据、内容验真、锚点缺失 | `unregistered`（「来源未知」恢复流程） | 换机/密钥丢失流程，不静默重算 |
| 有收据、内容验真、锚点相符 | `verified` | — |

### 2.2 文档级问题（全部进入「需处理」，不静默重算）

- `missing-event-in-document`：收据存在而文档事件缺失（B-11 删除）；
- `document-order-mismatch`：文档顺序 ≠ 链序——内容均验真时投影仍按链序折叠（B-16），顺序异常如实标注（非致命）；
- 同一 event_id 文档内重复：逐块独立裁定（篡改副本单独判 invalid），重复如实标注；
- `duplicate-receipt` / `receipt-chain-broken` / `anchor-mismatch` / `anchor-missing`：收据库或锚点异常。

### 2.3 诚实声明（对齐基准 3.5）

同 OS 权限的恶意 agent 仍可能访问本地锚点文件——本机制承诺「可识别多数手工篡改与无收据伪造」，不承诺对抗同权限攻击者。
